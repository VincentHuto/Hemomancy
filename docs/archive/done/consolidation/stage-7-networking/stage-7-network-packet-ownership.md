# Stage 7: packet authority and client-state ownership

This records the implemented Stage 7 networking changes in the 2026-09-25 checkout: menu validity gates, dimension-scoped active-rite delivery, and client projection cleanup. Protocol IDs, codecs, and registration directions are unchanged. The existing [packet registration index](../packet-registration-index.md) lists every entry; this sheet traces representative packet handlers through validation, mutation, reply scope, and client cleanup.

## Registration is centralized; behavior is not

[PacketHandler.onRegisterPayloads](../../../src/main/java/com/vincenthuto/hemomancy/common/network/PacketHandler.java) currently contains 174 registrations: 42 `playToServer`, 98 `playToClient`, and 34 `playBidirectional`. `TYPE`, `STREAM_CODEC`, and handler are paired in that one method. Direction in this method describes what the protocol permits, not necessarily the only side a handler actually uses. For example, `StartCentrifugeButtonPacket` and `ChangeSelectedManipPacket` are registered **bidirectionally** but their gameplay actions run on the server. Preserve the registered direction until caller and compatibility checks justify narrowing it.

`PacketHandler.sendToPlayer` is also a domain operation for `OpenDialoguePacket`: it queues pending whispers, clears monolith context for ordinary entity dialogue, and decorates the tree before sending. Replacing it with a transparent send wrapper would change dialogue behavior. Other packet families often use `PacketDistributor` directly for nearby, tracking, or all-player delivery.

These examples distinguish **current-menu actions** (`menu type`, `stillValid`, matching block/position where applicable, action permission, mutation) from **world/player actions** (ownership, distance or dimension, progression/cost, target re-resolution, mutation). Stage 7 adds the two missing menu gates directly in their handlers; each feature retains its gameplay rules, without introducing a shared validation wrapper.

This is a useful comparison for Chamber cleanup, not a reason to merge the feature-specific payloads. |

Client state is described by **recipient scope**, **full replacement versus incremental update**, **end signal or expiry**, **login/late-observer rebuild**, and **logout/world-change clear**. Active rites now use level-scoped replacement and entering-player snapshots. Session and level cleanup is separate from server delivery and does not change payload formats.
