# World persistence and gameplay data reloads

## Saved world state

[StillWatersSavedData](../../src/main/java/com/vincenthuto/hemomancy/common/rite/unstained/StillWatersSavedData.java), [PaleConsecrationSavedData](../../src/main/java/com/vincenthuto/hemomancy/common/rite/unstained/PaleConsecrationSavedData.java), and [LetheCovenantSavedData](../../src/main/java/com/vincenthuto/hemomancy/common/rite/unstained/LetheCovenantSavedData.java) use similar timed-zone records. The [Stage 4 zone audit](stage-4-unstained-zones/README.md) maps their exact NBT keys, expiry rules, dimension routes, and geometry. [BloodMoonSavedData](../../src/main/java/com/vincenthuto/hemomancy/common/event/worldevent/BloodMoonSavedData.java), [FoundingFaneSavedData](../../src/main/java/com/vincenthuto/hemomancy/common/event/worldevent/FoundingFaneSavedData.java), [CircusPavilionSavedData](../../src/main/java/com/vincenthuto/hemomancy/common/entity/npc/circus/CircusPavilionSavedData.java), and [VagrantMindEncounterData](../../src/main/java/com/vincenthuto/hemomancy/common/worldgen/VagrantMindEncounterData.java) own other world records. Some resolve storage from the overworld; Vagrant Mind uses the passed level. That scope difference is gameplay behavior.

**Target contract:** every saved-data class should state its storage dimension, stable data name, entry identity, NBT version/default behavior, mutation methods, `setDirty()` policy, and expiration/pruning owner. A small common codec for genuinely identical zone entries may help; a single giant world-state file would hide ownership. Never rename a saved-data key or NBT field as part of a cleanup without a migration path for existing worlds.

**First slice:** the Stage 4 field comparison is complete. Coordinate only their identical 100-tick Overworld pruning first; consider common field serialization afterward. Keep separate public types, keys, radius units, and active effect geometry.

## Resource reloads

[Hemomancy.java](../../src/main/java/com/vincenthuto/hemomancy/Hemomancy.java) registers listeners including [ItemInquiryLoader](../../src/main/java/com/vincenthuto/hemomancy/common/entity/npc/dialogue/inquiry/ItemInquiryLoader.java), [DiscoveryInscriptionLoader](../../src/main/java/com/vincenthuto/hemomancy/common/block/inscription/DiscoveryInscriptionLoader.java), [IchorianSigilLoader](../../src/main/java/com/vincenthuto/hemomancy/common/rite/sigil/IchorianSigilLoader.java), and [CardinalRiteFloorLoader](../../src/main/java/com/vincenthuto/hemomancy/common/rite/floor/CardinalRiteFloorLoader.java). [SuccessionProfessions](../../src/main/java/com/vincenthuto/hemomancy/common/entity/npc/harbinger/succession/SuccessionProfessions.java) registers through its own event handler. Cardinal Rite floors and Ichorian Sigils now share `JsonResourceReloadListener` for folder discovery, JSON reading, ID derivation, error logging, and publication. Other loaders retain their existing implementations.

**Target contract:** share a narrow JSON-resource scanning utility that preserves namespace IDs, per-file diagnostics, and reload snapshot semantics. Keep each schema parser and registry independent. Record whether malformed entries are skipped or invalidate the reload; make that deliberate and consistent within each data family. HutosLib owns part of the book/dialogue pipeline, so check its existing listener before adding local infrastructure.

**Implemented slice:** `JsonResourceReloadListener` uses Minecraft's `FileToIdConverter` and UTF-8 resource readers, retaining namespace/nested IDs and resource-pack priority. Invalid JSON, schema errors, and unreadable files are logged individually and skipped. Preparation builds an immutable map without publishing; apply publishes the complete replacement after the reload barrier. Empty reloads remove stale entries, while previously returned snapshots remain stable. Floor focus validation and sigil awakened-form fallback stay in their separate parsers. Existing folders and listener registrations are unchanged.
