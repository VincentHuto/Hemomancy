# Stage 2: player snapshot dispatch audit

This records the implemented Stage 2 dispatch boundary in the 2026-09-25 checkout. Tendency and vascular owner snapshots now share lifecycle subscriptions in `HemoCapabilityRegistrar`; their feature classes retain state access and mutation-triggered sends. Packet formats and recipients are unchanged. Stage 1 mapped [storage and lifecycle](../capability-lifecycle-and-observer-sync.md) and [combat/death event order](../stage-1-capabilities/README.md).

## First matching pair: tendency and vascular

Both attachments are player state registered with `copyOnDeath` in [HemoAttachmentTypes](../../../src/main/java/com/vincenthuto/hemomancy/common/capability/HemoAttachmentTypes.java), exposed through player capability keys in [HemoCapabilityRegistrar](../../../src/main/java/com/vincenthuto/hemomancy/common/capability/HemoCapabilityRegistrar.java), and sent only to the owning player. The registrar's login, dimension-change, and respawn handlers call `sendOwnerSnapshots`, which calls tendency and then vascular `syncOwnerSnapshot` exactly once each. They have no `StartTracking` subscriber or preparation/migration work in this dispatch path.

The request packets are registered in [PacketHandler](../../../src/main/java/com/vincenthuto/hemomancy/common/network/PacketHandler.java), but a source-wide search found no construction/send call for either C2S request outside their own decode methods. Treat them as registered fallback paths, not evidence that clients currently request these snapshots.

The packet codecs are similar but are **not** part of the dispatch seam. Both encode one accumulating NBT compound per enum entry and decode one compound per entry. Tendency fills a missing enum value with `0`; vascular fills it with `100`. `BloodTendency.getTendency()` returns an effective map including transient alignment, while `VascularSystem.getVascularSystem()` returns its held map. The dispatcher preserves the existing packet types, per-feature send counts, enum/default behavior, and payload construction. The pair now has an explicit order: tendency's effective values first, then vascular's stored values. This does not establish ordering against unrelated event subscribers. Codec cleanup remains separate.

## Implemented dispatch boundary

The six feature-owned lifecycle subscriptions were replaced by three registrar subscriptions and one private dispatcher. Public `syncTendency` and `syncVascular` change-path APIs and their mutation callers remain intact. Login/dimension tendency retains its empty-map fallback; vascular requires its capability; respawn requires both, behind the registrar's server-side guard.

Payload classes, packet IDs, codec bytes, client handlers, attachment IDs, save NBT, and `copyOnDeath` policy are unchanged. The shared responsibility is the lifecycle trigger and owner delivery. Other capability families and tracking snapshots remain with their existing owners; the table above describes boundaries for any future extraction.
