# Manipulation improvement work plan

Derived from the [7 September manipulation audit](../MANIPULATION_GAMEPLAY_BALANCE_VISUAL_AUDIT.md). This breaks its findings into **32 actionable tasks across six work areas**, with dependencies and completion checks. It covers all **97 active powers**; retired registrations stay compatibility-only.

Work areas 1 and 2 (M01–M12) have been implemented; see the [correctness results](01-correctness-results.md) and [targeting/casting results](02-targeting-and-casting-results.md). Area 3's [first implementation pass](03-acquisition-results.md) covers acquisition fixes, family verification and cost guidance; live acquisition checks and post-balance repricing remain open. Area 4's [balance implementation](04-balance-results.md) is in place, with live comparisons still open. Area 5's authored presentation pass and Area 6's acceptance pass are recorded; full live acceptance remains open. The original audit is the pre-fix reference; recheck its findings against current source before subsequent changes.

The [Animus and Mortem presentation pass](10-animus-mortem-visuals.md) records the liquid blood, decay and fungal shader treatment and its validation.

Use a task ID to pick up work, for example **“Implement M01”**. For tickets marked “several patches” or “one power per patch,” select the first named power/family, complete its acceptance checks, then continue within the ticket. Do not combine the whole backlog into one patch.

## Execution rules

- **Client/VFX requirement:** every manipulation must visually deliver its concept with intentional shape, material, motion and impact. Random vanilla particles are not a finished signature effect. Create custom assets/rendering where needed; Crimson Coronation must visibly summon bloody swords. Apply the [visual standard and live completion gate](05-visuals-and-audio.md#required-visual-standard-for-every-manipulation) to the whole roster.

- Treat audit numbers as baseline evidence, not predetermined final balance targets. Measure accepted damage/healing, blood paid, duration and shared cooldown under comparable conditions.
- Fix shared causes in their owner after tracing callers; avoid adding a new generic framework when an existing helper fits.
- Keep IDs, saves, learned memories, family selection and useful baseline forms intact. Preserve unrelated dirty work and authored models/effects.
- Choose and record ordinary implementation details inside the task. No separate procedural design approval or worktree is needed.
- Use focused automated checks for behavior defects and resource validation for assets. Validate gameplay and presentation live where that is the acceptance criterion. Build success alone does not establish balance or visual quality.
- Stage ordering is guided by dependencies, not the file number: **M14 recipe tuning follows M18–M25 combat/utility tuning**. M13/M15/M16 can be investigated earlier. M17 display copy follows settled costs. M31 audio can follow its lifecycle prerequisites without waiting for every visual task.
