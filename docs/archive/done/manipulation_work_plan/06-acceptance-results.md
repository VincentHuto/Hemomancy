# Area 6: acceptance results

7 September 2026 · [M32](06-acceptance.md) · [Work-plan index](README.md)

**Acceptance remains open.** This pass reruns the server regressions, adds a repeatable two-client dedicated-server scenario, fixes defects exposed by it, and records a result for all 97 active powers. It does not certify the whole roster's balance or visual quality from compilation or static source inspection.

## Defects found and corrected

- **Hematic Flare:** the remote empty-target cast spent blood. Its private selection also bypassed shared ally/PvP protection. Preflight now requires a visible, permitted target using the same range as execution; failure occurs before payment, mastery or cooldown. Its successful-hit regression exposed a client-only particle factory on a dedicated server; particle data now travels through the existing server-safe path.
- **Funeral Bell:** the remote observer lost health despite `pvp=false`. Target selection now applies shared harm permission before damage or Wither. The shared damage helper also rejects protected recipients; all eight callers were traced as offensive damage paths. The regression includes poisoned protected players and owned wolves so blocked damage cannot conceal a status leak.
- **Hematic Stake tests:** formation fixtures were Degree 0 while the current recipe requires Degree V. Corrected fixture prerequisites and the recipe assertion; the actual progression gate is unchanged.
- **Stale manipulation source checks:** repaired moved renderer/crafting paths, current Conductive Mark values, current tree prerequisites/positions and Thread Ripper's exceptional reward placement. Remaining failures are listed separately, not silently waived.

Changed production owners: [HematicFlareManip](../../src/main/java/com/vincenthuto/hemomancy/common/manipulation/lux/HematicFlareManip.java), [FuneralBellManip](../../src/main/java/com/vincenthuto/hemomancy/common/manipulation/mortem/FuneralBellManip.java), [ManipulationCombatHelper](../../src/main/java/com/vincenthuto/hemomancy/common/manipulation/ManipulationCombatHelper.java). No ranks, recipes, blood prices or saved IDs changed in this pass.

## Dedicated server and two real clients

[Fixture](../../src/gameTest/java/com/vincenthuto/hemomancy/gametest/ManipulationRemoteAcceptance.java) · [launch configuration](../../tools/misc/manipulation-remote-acceptance.init.gradle)

Two development clients, Area6Caster and Area6Observer, connect over TCP to a dedicated server at `127.0.0.1:25576`. The caster uses the vanilla item-use path and actual manipulation network packets. Terrain, prerequisites, blood, equipment and stationary hostiles are supplied in disposable build directories. This is networked gameplay evidence, not a measured survival route or WAN-latency test. The observer independently receives production visual packets.

**Final rerun: 19 assertions passed across 11 scenes; zero failed assertions.** [Durable server evidence](evidence/area6/remote-after-fixes.txt). Both clients and the dedicated server completed their runs successfully. Flare's empty-target cast preserved blood/cooldown; Bell left the protected observer at 20 HP.

The first complete run exposed the Flare miss and Bell PvP defects. [Pre-fix server evidence](evidence/area6/remote-before-fixes.txt) retains the failed assertion and Bell's observer-health loss. Checks now also assert observer health for each later cast. An earlier client startup failed while another Gradle build rewrote HutosLib's jar; the launch configuration keeps the already-built dependency jar stable during concurrent runs.

## Reproduce and finish

1. Build dependencies before opening the remote clients: `./gradlew.bat compileGameTestJava`. The opt-in init script expects the built HutosLib jar and prevents it being rewritten while clients read it.
2. Use the disposable `build/area6-server` directory with `server-ip=127.0.0.1`, `server-port=25576`, `online-mode=false`, `pvp=false`, `spawn-protection=0` in `server.properties`. These settings are for this local fixture only.
3. Start `./gradlew.bat -I tools/manipulation-remote-acceptance.init.gradle runServer`, then run `runArea6Caster` and `runArea6Observer` with the same init script in separate terminals. Do not run dependency builds concurrently with the clients. The scenario begins when both named clients join, captures to their build directories, logs each assertion, and exits automatically. A ten-minute tick deadline stops an incomplete server.
4. Complete the normal [acquisition checkpoints](03-acquisition-results.md#early-route--source-backed-checkpoints), with travel/drop/crafting effort recorded. Use that evidence to settle M14's remaining recipe comparison.
5. Review the pending powers above in moving encounters, then do Avatar/staff clipping, reduced particle settings, overlapping zones, audio, and a remote boss encounter. Prioritize Well/Bell's observed presentation weaknesses.

M32 remains unchecked until those acceptance limits are resolved. The original audit remains a historical baseline with this report linked as its current follow-up.
