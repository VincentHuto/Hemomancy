# Mnemonist Puppet Design

## Goal
Add the first playable Mnemonist Puppet prototype as a bounded Degree 5 puppeteer summon that attacks through simplified blood-memory echoes rather than full action replay.

## Scope
The puppet is a normal Marionette Crossbar summon, not a standalone item. It uses the owner-attuned Crossbar UUID, player-wide active cap, Crossbar call charge, per-body charge upkeep, field recall, and trial behavior.

V1 records only compact attack memories for the puppet's current target:
- target identity
- clamped incoming damage amount
- game time
- whether the memory was generated by a replay

It does not record movement, animations, projectiles, inventory state, AI decisions, or arbitrary world events.

## Behavior
When a living entity that is currently targeted by a nearby Mnemonist Puppet takes damage, the puppet stores a memory if the damage is positive and is not itself replay damage. The buffer holds six memories and drops the oldest entry when full. Memories expire after eight seconds.

Every two seconds, a bound puppet with a valid target consumes one fresh matching memory and deals reduced magic damage to that same target. Replay damage is clamped so large hits and boss attacks do not create runaway burst. The replay emits restrained red/gray particles around the target and a quiet memory-themed sound. Replays cannot record themselves.

The puppet has weak direct combat stats. Its value comes from echoing recent pressure against one target, so it is best against sustained fights rather than trash clearing.

## Integration
Add `mnemonist_puppet` to `PuppeteerSummonDefinitions`, `PuppeteerSummonFactory`, `EntityInit`, client renderer registration, language, trial recipe data, and the developer reference. The entity extends the existing bound summon pattern used by `GoreboundHulkEntity` and `MarrowSpitterEntity`.

The event hook lives in a focused summon event class and scans nearby `MnemonistPuppetEntity` instances around the damaged target. This keeps global state out of the player capability layer and avoids adding networking for V1.

## Tests
Pure rule tests cover buffer cap behavior, stale-memory expiry, replay damage clamping, replay recursion prevention, and target mismatch rejection. Runtime verification uses `compileJava`, the focused direct rule test, `test`, and `build`.
